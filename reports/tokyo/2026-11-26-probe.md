How a trigger becomes a pair, the limits and the record kinds are in `docs/probe.md`; in short: paper's +500 ms "quote still displayed" → gates (halted / reconcile / STOP / loss cap / busy) → size q = max(5, Lighter min, PM min, ⌈$1/ask⌉) whole shares → skip if q > Lighter displayed, a leg > $10, open cost over $40 L / $30 PM, or tracked balance short → Lighter IOC at the trigger price → Polymarket FAK of the complementary token at min(0.99, ask + 3¢), up to 3 retries within 2 s → unwind the remainder on Lighter (IOC, best ∓ 5¢) and log `unhedged`. One execution at a time. Any ambiguous order (no terminal status in 3 s, unparseable PM response, exception mid-pair) → `halt`: nothing new until a restart, and **no blind unwind**.

**Where it differs from the brief's letter (deviations):**
- **Interpreter**: venv instead of `/usr/bin/python3` (§1.7).
- **Paper records kept as is**: the brief asks for "the same record kinds and ids as the paper trader". The probe logs all of them unchanged, including the paper's `hedge` and `settle` (the paper *model*'s hedge and settle, now useful as a per-trigger reference); the probe's real execution uses new kinds (`l_order`, `l_fill`, `pm_order`, `pm_fill`, `pair`, `unwind`, `unhedged`, `probe_settle`, …).
- **Clip sizes are whole shares** (rounded up): fits both size steps and keeps Polymarket BUY amounts at ≤ 2 decimals (the maker-amount precision rejection Octopus hit in #26). A Lighter fill or a PM partial that leaves < 1 share, or a remainder below both venues' 5-share minimum, cannot be hedged or unwound: it is **held to settlement** and logged (`unhedged.residual_held`).
- **Loss cap counts a pair's locked P&L at hedge time** (plus unwind losses at once, and the settlement residual), so a run of losing pairs stops the probe the same day rather than ~15 min later.
- **Dry logs go to `~/lp-arb/probe-dry`** and carry `mode: dry`; the live ledger ignores them. Mixing would make the live reconcile see fake positions.
- **`API_KEY_INDEX` and `SIGNATURE_TYPE` are not redacted** (1–3 digit selectors; redacting "2" corrupts every number). They are never logged deliberately. Everything else from SSM, plus the derived PM API key/secret/passphrase, is.
- **The probe refuses live mode if reused code changed** (sha256 pins on 6 Stat_Arb files and rd3_live.py) — an addition, not in the brief.
- **Settlement after a restart**: windows that ended while the probe was down are settled from Gamma + Lighter's REST `outcome`, so their open cost does not stay reserved. Addition.

## 7. Open questions (for the operator / first live hour)

1. **`bo_positions` for this sub-account**: the schema is from a public account; after the first `l_fill`, the next `balance.lighter_positions` must show `{<market_id>: ±q}`. If it stays `{}`, the reconcile is blind — stop.
2. **Can a Lighter sub-account trade binary options?** The docs only exclude public pools and the insurance fund. First `l_order` will tell (a rejection reason is logged).
3. **Lighter IOC status latency**: the probe gives `account_orders` 3 s to show a terminal status, polling every 250 ms. If fills are confirmed later than that, every trade halts as ambiguous. A websocket `account_market/{market}/{account}` subscription (auth token) would be faster and cheaper; not built.
4. **IP rate limit is shared**: public Lighter reads from lp-arb-paper, the probe, xsmom, ladder and the recorders all count against the box's 60/min IP budget; the probe's signed/authenticated calls count against the sub-account's L1 budget. A 429 during a fill poll ends in `halt`.
5. **Polymarket FAK partials** leave remainders under the 5-share minimum that can be neither hedged nor unwound (held to settlement). At 5-share clips any PM partial does this. Expect some `unhedged.residual_held` > 0.
6. **Fees actually charged**: Polymarket `fee_rate_bps` per trade and Lighter `taker_fee` per trade are logged ~5 s after each fill (`fees`), but P&L uses the model (Gamma rate / 1%·p(1−p)) until someone compares them.
7. **Hedge chase vs frozen rule**: the brief's ask + 3¢ chase is wider than the shadow candidate's +1¢ no-chase (`PROBE_PM_LIMIT_OVER_ASK` in paper.py); the paper's 31/72 losing pairs were hedge slippage, so watch `pair.pm_px` vs `trigger.pm_px`. The dry run already shows it: trigger 1795650300-b paired at −0.82 ¢/sh, where paper had "hedge size < 5" (§5).
